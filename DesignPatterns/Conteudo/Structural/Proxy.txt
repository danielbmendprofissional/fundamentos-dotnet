======================================= DESIGN PATTERNS =======================================

======================================= STRUCTURAL 
================== PROXY

SOLID TRABALHADO: OCP

INTENÇÃO OFICIAL:

Fornecer um substituto ou representante de outro objeto para controlar o acesso a ele.
Ele age como um intermediário, permitindo que você adicione funcionalidade adicional, 
como controle de acesso, cache ou registro, sem modificar o objeto original.

Tem várias variações, incluindo:
	- Proxy Virtual: controla o acesso a um objeto caro, criando-o apenas quando necessário.
	Muitas vezes usado para carregamento tardio (lazy loading)/cache.

	- Proxy Remoto: representa um objeto localizado em um endereço diferente (por exemplo, 
	em outro servidor ou no mesmo servidor, mas subsistema fora do meu código).

	- Proxy de Proteção: controla o acesso a um objeto com base nas permissões do 
	usuário.

	- Proxy Inteligente: adiciona funcionalidade extra ao objeto original, para saber quando
	e como executar certas ações.

	- Proxy de Cache: armazena em cache os resultados de operações caras para melhorar 
	o desempenho.

APLICABILIDADE:
	- Controle de acesso: quando você deseja controlar o acesso a um objeto sensível ou caro.
	- Cache: quando você deseja armazenar em cache os resultados de operações caras para 
	melhorar o desempenho.
	- Registro: quando você deseja registrar chamadas para um objeto sem modificar seu código.
	- Logs.
	- Ligar seu sistema a outro sistema remoto.

================== CONSEQUÊNCIAS

Benefícios:
	- Cliente não sabe se está lidando com o objeto real ou com o proxy.
	- Pode adicionar funcionalidade extra sem modificar o objeto original. (OCP)
	- Proxy funciona mesmo se o objeto real não estiver disponível.
	- Pode melhorar o desempenho através de cache ou carregamento tardio.
	- Pode controlar o acesso a objetos sensíveis.
	- Pode controlar ciclo de vida de objetos caros.

Malefícios:
	- Mais classes e objetos no sistema, aumentando a complexidade.

================== IMPORTANTE
- Semelhante ao COMPOSITE e DECORATOR, porém com as intenções diferentes.

- Você não exclui a classe original, você a envolve com o proxy.

- Virtual x Cache:
	- Virtual Proxy: cria o objeto real apenas quando necessário. (apenas 1 objeto/instânica)
		Ele aguarda somente a hora certa para precisar criar o objeto real.

	- Cache Proxy: armazena em cache os resultados de operações caras. (pode ter vários objetos/instâncias)
		Ele guarda o objeto criado para reutilizá-lo depois.
